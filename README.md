# DFA Transition Table Generator (DFATT)

DFATT is a command-line utility that extracts the DFA (Deterministic Finite Automaton) transition table generated by [Flex](https://github.com/westes/flex) and presents it in two forms:

- A readable transition table printed to the terminal.
- A directed graph of the automaton, saved as `graph.png`.

It also provides an option to exclude Flex's external ghost states when determining the states to include in the generated table.

## Features

- **Flex DFA table extraction** — uses the bundled lexer to extract the DFA transition arrays from a Flex-generated C source file.
- **Transition table generation** — reconstructs state transitions for the input symbols and prints the resulting table to standard output.
- **DFA graph visualization** — uses NetworkX and Matplotlib to generate a directed graph with states as nodes and input symbols as edge labels. Multiple symbols leading between the same pair of states are grouped into one edge label.
- **State-count optimization flags** — supports `-O0`, `-O1`, and `-O2` to select the raw or reduced state-count path.
- **Temporary-file cleanup** — removes generated executables, the extracted header, and intermediate transition data when the script exits. The generated graph is retained.

## How It Works

DFATT processes a scanner generated by Flex through the following pipeline:

1. **Extract:** `table_lexer.c` scans the Flex-generated C source and extracts the DFA transition-table arrays.
2. **Generate a header:** The extracted arrays are written to a temporary `dfa_table.hpp` header.
3. **Reconstruct transitions:** `main.cpp` uses the extracted arrays to calculate the next state for each relevant input symbol.
4. **Visualize:** `plot.py` reads the intermediate data and generates the directed automaton graph in `graph.png`.

The shell script, `dfatt.sh`, orchestrates compilation, execution, visualization, and cleanup.

## Requirements

Make sure the following tools and libraries are available:

- **Flex** — to generate the scanner source file.
- **gcc** — to compile the bundled extraction lexer.
- **g++** — to compile the C++ transition-table driver (C++11 or later).
- **Python 3** with \`venv\` support
- **NetworkX**
- **Matplotlib**

Run DFATT's Python visualization step inside a virtual environment so its dependencies are isolated from your system Python installation.

Create and activate a virtual environment from the repository root:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Install the required Python packages inside the activated environment:

```bash
python -m pip install --upgrade pip
python -m pip install networkx matplotlib
```

Keep this environment activated whenever you run DFATT. 

## Usage

### 1. Generate the Flex scanner

Write a Flex specification and generate its C source file:

```bash
flex -o lex.yy.c scanner.l
```

### 2. Set up and activate the Python virtual environment

If you have not already created the environment, follow the [requirements](#requirements) instructions above. Activate it before running the script:

```bash
source .venv/bin/activate
```

### 3. Run DFATT

Make the driver executable if necessary:

```bash
chmod +x dfatt.sh
```

Run it with the generated scanner source:

```bash
./dfatt.sh lex.yy.c
```

To select a state-count optimization mode, pass one of the supported flags after the input file:

```bash
./dfatt.sh lex.yy.c -O0
./dfatt.sh lex.yy.c -O1
./dfatt.sh lex.yy.c -O2
```

When you are finished, you can leave the virtual environment with:

```bash
deactivate
```

### Optimization modes

| Flag | Behavior |
| --- | --- |
| -O0 | Uses the raw number of states from Flex's `yy_base` array. This is also the default when no flag is supplied. |
| -O1 | Uses the reduced state count derived from `yy_def[1]`, excluding the external ghost-state range. |
| -O2 | Currently follows the same reduced-state path as `-O1`. |

> **Note:** `-O1` and `-O2` are accepted by the command-line interface, but the current implementation maps both to the same state-count selection. They should not be interpreted as separate optimization passes.

## Output

After a successful run, DFATT produces:

| Output | Description |
| --- | --- |
| Terminal output | The DFA transition table, with states as rows and input symbols as columns. |
| `graph.png` | A directed graph visualizing the DFA and its labeled transitions. |

The script uses `tt.txt` and `dfa_table.hpp` as intermediate files. These, along with the temporary executables, are cleaned up when the script exits; `graph.png` is retained.
