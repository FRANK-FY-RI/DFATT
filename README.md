# DFA Transition Table Generator (DFATT)

DFATT is a command-line tool that extracts the compressed DFA (Deterministic Finite Automaton) transition tables from a Flex-generated C scanner, reconstructs the transitions, and presents the automaton in two forms:

- A transition table printed to the terminal.
- A directed graph saved as `graph.png`.

DFATT works with the scanner's generated transition arrays rather than attempting to parse or interpret the original regular expression.

## Features

- **Flex table extraction:** A bundled Flex-generated lexer scans the generated C source and emits the DFA arrays required by the C++ driver.
- **Transition reconstruction:** Reconstructs state transitions using Flex's equivalence classes, meta-equivalence classes, base offsets, fallback states, check table, and next-state table.
- **Terminal transition table:** Prints states as rows and input symbols as columns.
- **DFA graph visualization:** Uses NetworkX and Matplotlib to draw a directed graph. Transitions between the same pair of states are combined into one edge label.
- **Byte-oriented symbol handling:** Keeps input symbols as integer byte values in the intermediate table. This avoids relying on terminal encoding for whitespace, control characters, or high-byte values.
- **Readable symbol names:** Uses `symbol_names.tsv` to display printable characters, control-character mnemonics, and high-byte hexadecimal labels consistently in the terminal and graph.
- **Optimization levels:** Supports 3 optimization levels using `-O0`, `-O1`, and `-O2`. 
- **Temporary-file cleanup:** Removes generated executables, the extracted header, and intermediate transition data on the normal execution path. The generated graph is retained.

## How It Works

The pipeline operates on a C source file generated by Flex:

1. **Generate the scanner:** Flex converts your `.l` specification into a C source file (commonly `lex.yy.c`).
2. **Extract the tables:** `dfatt.sh` compiles and runs `table_lexer.c`, which scans the generated source and writes the selected DFA table declarations to a temporary `dfa_table.hpp` header.
3. **Compile the driver:** The script compiles `main.cpp` as C++11. The driver includes `optimizations.hpp`, which in turn includes the generated header.
4. **Identify input symbols:** The driver examines all 256 possible byte values and selects those whose `yy_ec` equivalence class is greater than 1. Values in equivalence classes 0 and 1 are not included as table columns.
5. **Reconstruct transitions:** For each included state and selected byte value, `nextstate()` follows Flex's compressed-table lookup procedure:
   - Map the byte through `yy_ec`.
   - Check `yy_chk` at the current state's `yy_base` offset.
   - Follow `yy_def` fallback states when the check does not match.
   - Apply `yy_meta` when the fallback reaches the external ghost-state range.
   - Read the resulting state from `yy_nxt`.
6. **Write intermediate data:** The driver prints the human-readable table and writes the numeric transition data to `tt.txt`.
7. **Draw the graph:** `plot.py` reads `tt.txt`, resolves byte values through `symbol_names.tsv`, groups labels for edges that share the same source and destination, and saves `graph.png`.

The shell script coordinates these steps and installs exit cleanup for the generated build artifacts and intermediate files.

## Requirements

### System tools

- **Flex** — generates the scanner C source from your `.l` specification.
- **GCC (`gcc`)** — compiles the bundled extraction lexer.
- **G++ (`g++`)** — compiles the transition-table driver with C++11 support or later.
- **Python 3** — runs the graph visualizer.
- **Python `venv` support** — recommended for isolating Python dependencies.

### Python packages

- **NetworkX** — constructs and manages the directed graph.
- **Matplotlib** — draws and saves the graph.

Create and activate a virtual environment from the repository root:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Install the Python dependencies:

```bash
python -m pip install --upgrade pip
python -m pip install networkx matplotlib
```

Keep the environment activated when running DFATT so that `python3 plot.py` can import the installed packages. The script does not create or activate the virtual environment automatically.

## Usage

### 1. Write a Flex specification

Create a scanner specification, for example `scanner.l`.

### 2. Generate the scanner C source

Run Flex from the repository root (or provide a path to the generated source when invoking the script):

```bash
flex -o lex.yy.c scanner.l
```

### 3. Set up the Python environment

Create and activate the virtual environment and install the dependencies as described in [Requirements](#requirements):

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install networkx matplotlib
```

If the environment already exists, only activation is needed:

```bash
source .venv/bin/activate
```

### 4. Run DFATT

From the repository root:

```bash
chmod +x dfatt.sh
./dfatt.sh lex.yy.c
```

To choose a state-count mode, pass one flag after the scanner source:

```bash
./dfatt.sh lex.yy.c -O0
./dfatt.sh lex.yy.c -O1
./dfatt.sh lex.yy.c -O2
```

When finished, leave the virtual environment with:

```bash
deactivate
```

### Command-line arguments

The intended invocation is:

```text
./dfatt.sh <scanner-source.c> [ -O0 | -O1 | -O2 ]
```

The scanner source is supplied as the first argument and read by the extraction lexer through standard input redirection. The optional flag is forwarded to the C++ driver.

The driver rejects unknown flags and more than one driver argument. 

## Optimization levels

The modes select how many entries from Flex's state arrays are considered when generating the transition table.

| Flag | State-count selection |
| --- | --- |
| `-O0` | Uses the raw number of entries in `yy_base`, calculated from the array size. This is the default when no flag is supplied. |
| `-O1` | Uses `yy_def[1]` as the reduced state count, excluding the external ghost-state range from the selected state range. |
| `-O2` | Currently uses the same reduced state-count selection as `-O1`. |

> **Implementation note:** `-O1` and `-O2` are both accepted, but they currently map to the same code path in `get_no_of_states()`. They do not represent separate optimization passes or transformations of the DFA.

## Output and intermediate files

A successful run produces the following:

| File / output | Purpose |
| --- | --- |
| Terminal output | Human-readable transition table. Each row represents a state and each column represents a selected input symbol. |
| `graph.png` | Directed graph of the reconstructed DFA. |
| `tt.txt` | Temporary numeric representation consumed by `plot.py`. |
| `dfa_table.hpp` | Temporary header containing the extracted Flex DFA arrays. |
| `table_lexer` | Temporary executable built from `table_lexer.c`. |
| `main` | Temporary C++ driver executable. |

The intermediate `tt.txt` format is line-oriented:

1. Number of included states (excluding state zero).
2. Number of selected input symbols.
3. The selected input byte values, separated by whitespace.
4. One row per included state: the state number followed by its destination state for each selected symbol.

Symbol values remain numeric in this file. The plotting script uses `symbol_names.tsv` to obtain their display labels when rendering the graph.

On normal completion, the script's final exit trap removes `table_lexer`, `dfa_table.hpp`, `main`, and `tt.txt`. `graph.png` is not removed, so it remains available after the run; a subsequent run overwrites it. If execution fails before the final cleanup trap is installed, some intermediate files may remain.

## Symbol naming

`symbol_names.tsv` contains a mapping from byte values in the range 0–255 to display names. It includes:

- Control-character mnemonics such as `NUL`, `HT`, `LF`, and `CR`.
- `SPACE` for byte 32.
- Printable ASCII characters as their corresponding character labels.
- `DEL` for byte 127.
- Hexadecimal labels from `0x80` through `0xFF` for high byte values.

The mapping is used by both `main.cpp` (terminal table headings) and `plot.py` (graph edge labels). Keep this file in the repository root when running DFATT; both programs open it using a relative path. The mapping defines names for all byte values, but only values selected by the driver's `yy_ec[i] > 1` condition appear as table columns and graph labels.

## Implementation notes and limitations

- DFATT expects a Flex-generated C scanner whose table layout and declarations are compatible with the bundled extraction lexer and transition lookup logic. It is not a general-purpose parser for arbitrary C files or arbitrary DFA representations.
- The extraction lexer is bundled as generated C source (`table_lexer.c`), which was generated using [flex](https://github.com/westes/flex).
- The driver and visualizer expect to find `symbol_names.tsv` in the current working directory. Run the script from the repository root so the relative file paths resolve.
- The graph visualizer uses a deterministic spring-layout seed (`42`) for repeatable node placement.
- The graph is built from the generated transition edges. It does not separately add a start arrow or annotate accepting states using Flex's `yy_accept` table.
- The current state-selection flags only change the state range included in the generated output. `-O1` and `-O2` currently choose the same reduced state count.
- The Python script adds nodes through its edges; it does not explicitly add isolated states that have no represented incoming or outgoing edges.
